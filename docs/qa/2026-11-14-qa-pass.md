# QA pass, 14 November 2026

A test-and-report pass over Marswalk on `main`. Nothing in the code was changed. Each finding lists what I saw, where, a screenshot, a severity and a one-line fix.

## Scope and setup

- **Builds tested.** The production deploy at https://martian-map.fernando-haro-c.workers.dev and a local `npm run dev` of `origin/main`. Testing started on `f9d435a`. Five PRs merged during the pass (#165 storm look, #167 start screen, #168 shortcuts, #170 test fix, #171 partner panel), so I fast-forwarded to `54ca07b` and re-checked every finding the new code touches. Findings marked "seen on f9d435a" were not re-checked after the merge. By the end of the pass production served a build with the #167 start screen.
- **Viewports.** 1920 x 1080 and 1366 x 768 CSS px, device pixel ratio 2.
- **Tiers.** Forced with `?tier=high` and `?tier=low`. The dev build exposes `window.__marswalk` (teleport, stats, tier), which I used to jump between demo stops.
- **Browser.** The T3 preview browser renders WebGL with SwiftShader (software). It draws about 1 frame per second on both tiers, so **no frame-rate number in this report describes a real GPU**. I report triangles and draw calls from the engine's own `stats()` instead. Pointer lock is never granted in this browser, so after #167 I faked `requestPointerLock` to get past the start screen.
- **Not verified.** Rock LOD popping, boot prints while walking, head bob and memory growth over minutes of walking all need real frame rates. A 77 s walk moved the player 3 m.

Severity scale: **blocker** breaks a demo beat, **major** a judge will notice or it misstates data, **minor** visible but easy to miss, **polish** nice to have.

### F1. Environment strip never shows a value

- **Saw.** "– °C – m/s τ – – µGy" for 6 min of EVA, through both events. Reading the store at the same moment returned `dustOpacity: 3.17`, `doseUgy: 0.5`, `doseRateUgyH: 20`. The banner showed 0.3 µGy while the strip showed "–" for the same value.
- **Where.** Walk HUD, both tiers. `src/hud/Hud.jsx:110-114`: `EnvValue` renders `sourced ? value : '–'`, and nothing writes `sources['environment.*']`. `src/data/medaRad.js` (MEDA and RAD loaders) is imported by no running module, so temperature and wind are never set.
- **Screenshot.** [img/low-dust-storm-hud-1366.jpg](img/low-dust-storm-hud-1366.jpg), [img/low-walk-hud-1920.jpg](img/low-walk-hud-1920.jpg)
- **Severity.** blocker
- **Fix.** Register sources for the environment paths when the events and a MEDA replay write them, and start the replay in `src/state/simulation.js`.

### F2. The demo starts at the end of the route

- **Saw.** `mode: 'walk'` at load (`src/state/store.js:9`), spawn at (8, 70) (`src/engine/view.js:15`). The next waypoint panel says HAB, 737 m, bearing 136°. The #167 start screen copy says "Your EVA starts 70 m south of the rock" (`src/components/StartScreen.jsx:18`).
- **Screenshot.** [img/prod-walk-start-1920.jpg](img/prod-walk-start-1920.jpg), [img/newmain-start-screen-1366.jpg](img/newmain-start-screen-1366.jpg)
- **Severity.** blocker
- **Fix.** Merge PR #180 (#166), and update the start screen copy in the same change.

### F3. Slope legend says 25°, the data says 20°

- **Saw.** Legend "0–15° walkable, 15–25° caution, >25° no-go" and "Suit mobility limits: 15° caution, 25° no-go". hazards.json has `slope.no_go` 20 (DATA, xEVA con ops) and `slope.caution` 15 (SIM). The terrain shader and `src/sim/costGrid.js` use 20.
- **Where.** Plan mode, Map layers, Legend. `src/plan/layers.js:31-36` hard-codes the strings.
- **Screenshot.** [img/low-plan-slope-legend-25deg.jpg](img/low-plan-slope-legend-25deg.jpg)
- **Severity.** major
- **Fix.** Build the legend from `SLOPE_CAUTION_DEG` and `SLOPE_NO_GO_DEG` in costGrid.js instead of literals.

### F4. Walkback reads "home in 0 min" during the shelter route

- **Saw.** After the radiation alert, "WALKBACK MARGIN · home in 0 min" while the shelter panel says HAB 729 m, ETA 12 min.
- **Where.** Walk HUD, suit panel. `src/hud/Hud.jsx:102` formats `suit.walkbackSec`, which read 0 for as long as the shelter route was active.
- **Screenshot.** [img/low-radiation-alert-1366.jpg](img/low-radiation-alert-1366.jpg)
- **Severity.** major
- **Fix.** Compute the walkback along the shelter route when one is active.

### F5. Start EVA cannot proceed without pointer lock

- **Saw.** "Mouse capture was not granted, so the EVA stays paused." The button retries the same request. The mode switch behind the modal is inert, so there is no way into the scene.
- **Where.** Start screen (#167). `src/engine/pointerLock.js:100` returns false when `requestPointerLock` is missing or denied, and `handleResume` in `src/App.jsx:166-190` stops there.
- **Severity.** major. Desktop Chrome normally grants the lock on a real click, so the demo laptop is probably fine. It will fail in an iframe without `allow-pointer-lock`, on touch devices and in some remote-desktop or screen-share setups.
- **Fix.** After one failed attempt, offer "Continue without mouse capture" and fall back to drag-to-look.

### F6. Sampling has no crosshair and no listed controls

- **Saw.** A canvas click samples whatever sits under screen centre (`src/engine/sampling.js:190-197`), but no crosshair is drawn. In Walk before #167 the same click also requested pointer lock, so the first click could both lock and sample. The #167 controls help lists WASD, Shift, Mouse, Esc and H, but not P (photo), click (collect), E (bag), F (case), the layer keys, C (sources) or T (partner). The rock is only targetable at a pitch of about 0.9 rad from 1.2 m.
- **Where.** Walk mode; `src/components/ControlsHelp.jsx`.
- **Screenshot.** [img/low-sample-collect-cheyava.jpg](img/low-sample-collect-cheyava.jpg)
- **Severity.** major for the 1:20 beat if anyone other than the presenter drives.
- **Fix.** Draw a small crosshair that lights up when `sampling.status.target.inReach`, and add the sampling keys to the controls help.

### F7. Other functional notes

- **Layer carries into Walk with no legend.** Selecting Slope hazard in Plan keeps it on in Walk, and the whole view turns red and green with no legend or "layer: slope" chip. [img/low-radiation-alert-1366.jpg](img/low-radiation-alert-1366.jpg). minor. Fix: show the active layer name and legend in the HUD while a layer is on.
- **EVA clock survives a reload, the suit does not.** After a reload the start screen showed "EVA 0:18" with O2 back at 100 %. The clock persists in sessionStorage by design (`src/sim/missionClock.js:404`). minor. Fix: reset the clock with the suit, or persist both. For the demo, open a fresh tab before the take.
- **Stop card close button is labelled "Enter ×".** It reads like an action, not a close. polish. Fix: label it "Close" and keep the Enter hint as a kbd chip.
- **Sources modal background stays in the accessibility tree.** polish. Fix: mark the app root inert while the modal is open, as the #167 dialogs already do.
- **Unit tests.** On f9d435a one test failed (`StopCard.test.jsx`, Cheyava card radius). #170 fixed it. `npm run lint` passes with warnings, and CI is green on 54ca07b.

### D2. The Bright Angel stop is inside a no-go zone

- **Saw.** WP3 sits on a steady 30° slope (the assets README says so in "Layered outcrop"). The app's own slope layer paints it red. The route panel reports "Steepest 20°", exactly at the limit, and the slope-ahead zone fills the screen on arrival.
- **Where.** `public/marswalk/assets/route.json` WP3 (-40, -60), placeholder waypoint.
- **Screenshot.** [img/low-plan-slope-layer-1920.jpg](img/low-plan-slope-layer-1920.jpg), [img/high-brightangel-slope-zone.jpg](img/high-brightangel-slope-zone.jpg)
- **Severity.** major. The demo would send the astronaut into terrain the app calls no-go.
- **Fix.** Move WP3 to a stance point under 20° (the outcrop can stay on the slope above it) and re-run the planner.

### D3. Oxygen margin numbers disagree

- **Saw.** At rest the HUD shows +1192 min (19.9 h) DERIVED. hazards.json `suit.eva_duration_max` is 8 h (DATA). The Plan Go / No-go panel shows 242.8 min tagged SIM for "margin over the 30 min reserve". Both read as the same quantity. The Plan chips "O2 out" and "Battery out" say SIM while their own tooltip says "Registry entry: DERIVED".
- **Where.** `src/sim/suitModel.js:186` divides the tank by the resting O2 rate. `src/plan/RoutePanel.jsx:97-99` shows the end-of-route margin.
- **Screenshot.** [img/low-walk-hud-1920.jpg](img/low-walk-hud-1920.jpg), [img/low-plan-margin-mismatch.jpg](img/low-plan-margin-mismatch.jpg)
- **Severity.** major
- **Fix.** Cap the margin at the remaining EVA time, label the two margins differently ("margin now" and "margin at end of plan"), and make the chip tag match the registry.

### D4. Event banners contradict their source tags

- **Dust.** The banner text says "τ 8.00 · global storm profile · up to Curiosity's Gale 2018 storm, not Jezero" (hard-coded in `src/events/EventBanner.jsx:40`). Its DATA tag says "tau from the January 2022 Jezero dust storm; the ramp timing is SIM", from Mastcam-Z and MEDA. Both cannot be true, and the 2022 Jezero storm did not reach τ 8.
- **Radiation.** The banner shows 10.0 to 20.0 µGy/h with a DATA tag whose source is "RAD surface dose rate ... Hassler et al. 2014, first 300 sols" (the 0.21 mGy/day background, 8.75 µGy/h). The numbers come from the September 2017 event curve in `public/data/rad.json` (baseline 240 µGy/day).
- **Screenshot.** [img/low-radiation-alert-1366.jpg](img/low-radiation-alert-1366.jpg), [img/low-dust-storm-hud-1366.jpg](img/low-dust-storm-hud-1366.jpg)
- **Severity.** major. A judge who hovers the tag finds the contradiction.
- **Fix.** Point the radiation banner at `radEventAt().label` and the September 2017 provenance, and write the dust label from the same registry entry as the tag.

### D5. Matches with the assets README

- The sources screen's REAL / ARTISTIC / MODELLED summary matches "What is real and what is not" in `docs/marswalk-assets/README.md` word for word.
- The README says the Cheyava rock texture was not re-coloured when the ground was matched to Mastcam-Z. That is the cause of T4, not a documentation error.

### T1. Detail textures tile visibly between 30 and 110 m

- **Saw.** A regular quilt on flat ground from about 30 m out, on both tiers. It is clearest at grazing angles over the channel floor.
- **Where.** Walk, any flat stretch. `TERRAIN_FRAG`, `src/engine/shaders.js:132-138`. The second octave samples the same `gravel_nl.jpg` at 0.061 (16.4 m), so its pattern is the 2 m tile scaled up.
- **Screenshot.** [img/high-tiling-grid-crop.jpg](img/high-tiling-grid-crop.jpg), [img/high-walk-level-view.jpg](img/high-walk-level-view.jpg)
- **Severity.** major
- **Fix.** Rotate and offset the second octave by a non-integer amount (or use stochastic or hex tiling), and drop its weight past 60 m.

### T2. Slab texture draws a grid on the outcrop

- **Saw.** Pale squares on a 2 m grid across the light-toned band north of the start point, 40 to 100 m out.
- **Where.** `slab_nl.jpg` through `tMask`. The seams are in the file (see the table).
- **Screenshot.** [img/high-slab-grid-outcrop.jpg](img/high-slab-grid-outcrop.jpg)
- **Severity.** major
- **Fix.** Make `slab_nl.jpg` tileable (offset and heal the seams, flatten the low-frequency brightness) and add a second, rotated sample.

### T3. Slope-ahead zone is an unlit red lattice

- **Saw.** On steep ground the slope-ahead patch draws 2.7 m red quads on a 3 m grid with `MeshBasicMaterial` at 0.38 opacity. The quads ignore lighting, so sunlit and shadowed slopes turn the same bright red, and the 0.3 m gaps read as a black lattice.
- **Where.** `src/engine/slopeZone.js:7-17, 33`.
- **Screenshot.** [img/high-brightangel-slope-zone.jpg](img/high-brightangel-slope-zone.jpg)
- **Severity.** major at Bright Angel (D2), minor elsewhere.
- **Fix.** Draw the zone in the terrain shader (like the slope layer) or close the gaps and multiply by the terrain shading.

### T4. Cheyava Falls rock does not match its reference photo

- **Saw.** A saturated red rock with thick white vein lines. The Mastcam-Z frame on the stop card shows a pale tan rock. The ground around it was re-matched to Mastcam-Z on 14 November, which makes the rock stand out more.
- **Where.** `public/marswalk/assets/cheyava_color.jpg`. The README "Colour" section lists it under "Not changed".
- **Screenshot.** [img/high-cheyava-rock.jpg](img/high-cheyava-rock.jpg), [img/low-cheyava-stop-card-1366.jpg](img/low-cheyava-stop-card-1366.jpg), [img/low-sample-collect-cheyava.jpg](img/low-sample-collect-cheyava.jpg)
- **Severity.** major. It is the science target.
- **Fix.** Re-grade `cheyava_color.jpg` to the measured ratios (red:green about 1.5, green:blue about 1.8) and soften the veins to thin, broken lines.

### T6. Dust storm keeps full sun on the ground

- **Saw.** At τ 5.3 the sky and horizon close in, but the foreground keeps clear-day brightness and crisp rock shadows. Seen on f9d435a and again on 54ca07b after #165.
- **Screenshot.** [img/low-dust-storm-tau5.jpg](img/low-dust-storm-tau5.jpg) (before #165), [img/newmain-dust-storm-tau5.jpg](img/newmain-dust-storm-tau5.jpg) (after #165)

### Issue bodies

1. **Environment strip shows "–" for every value during the demo.** The Walk HUD environment strip never shows temperature, wind, tau or dose. `EnvValue` in `src/hud/Hud.jsx:110-114` renders "–" unless `sources[path]` is registered, and the dust storm and radiation events write `environment.dustOpacity` and `environment.doseUgy` without registering a source, so τ 3.17 and 0.5 µGy sit in the store unseen. The MEDA and RAD loaders in `src/data/medaRad.js` are never imported, so temperature and wind stay null. Register the sources where the values are written and start a MEDA sol replay in `src/state/simulation.js`. The 1:50 and 2:20 demo beats depend on it. See F1 in `docs/qa/2026-11-14-qa-pass.md`.
2. **Slope legend says 25° no-go; hazards.json and the shader use 20°.** `src/plan/layers.js:31-36` hard-codes "15–25° caution, >25° no-go" and "Suit mobility limits: 15° caution, 25° no-go". `public/data/hazards.json` has `slope.no_go` 20 (DATA, xEVA con ops), and the terrain shader and `src/sim/costGrid.js` already use 20, so the colours on the map disagree with the legend beside them. Build the legend from `SLOPE_CAUTION_DEG` and `SLOPE_NO_GO_DEG`. See F3.
3. **HUD panels overlap.** At 1920 x 1080 and 1366 x 768 the sampling checklist covers the top-right of the minimap, the NAV line covers the radio link chip, the event banner covers the heading readout and repeats the HUD alert strip text, and the science stop card covers the minimap. Measured boxes are in U1 of the report. Put the right column in one flex stack and show each alert in one place.
4. **Bright Angel waypoint WP3 sits on a 30° slope inside the no-go zone.** WP3 (-40, -60) in `public/marswalk/assets/route.json` is on a steady 30° slope, above the 20° limit. The slope layer paints it red, the route reports "Steepest 20°", and the slope-ahead patch fills the screen on arrival. Move the stance point to ground under 20° and leave the outcrop on the slope above it. See D2.
5. **Terrain detail textures tile visibly between 30 and 110 m.** `TERRAIN_FRAG` samples `gravel_nl.jpg` at a 2 m period and again at 16.4 m (`src/engine/shaders.js:132-138`), so the far octave repeats the same pattern and flat ground shows a quilt. `slab_nl.jpg` also has real seams (edge step 11 to 16 against 6 to 10 inside) and a 104 to 128 brightness spread, which draws a grid of pale squares on the outcrop band. Offset and rotate the second octave by a non-integer amount, make the slab texture tileable, and add a rotated second slab sample. See T1 and T2.
6. **Re-colour the Cheyava Falls rock to its Mastcam-Z reference.** `public/marswalk/assets/cheyava_color.jpg` keeps the old saturated red and flat white veins. The README "Colour" section lists it as not changed when the ground was matched on 14 November. The stop card shows the pale PIA26401 frame next to the 3D rock, so the mismatch is on screen at the science beat. Re-grade to red:green about 1.5 and green:blue about 1.8, and thin the veins. See T4.
7. **Oxygen margin readouts disagree and walkback reads 0 min on the shelter route.** At rest the HUD shows +1192 min (19.9 h) DERIVED, past the 8 h `suit.eva_duration_max` in hazards.json, because `src/sim/suitModel.js:186` divides the tank by the resting rate. The Plan Go / No-go panel shows 242.8 min tagged SIM for what reads as the same margin. During the radiation alert the suit panel says "home in 0 min" with the habitat 729 m away. Cap the margin at the remaining EVA time, label the two margins differently, and compute the walkback along the shelter route. See D3 and F4.
8. **Event banners and Plan chips contradict their own source tags.** The dust banner text in `src/events/EventBanner.jsx:40` says "global storm profile · up to Curiosity's Gale 2018 storm, not Jezero" while its DATA tag says "tau from the January 2022 Jezero dust storm". The radiation banner cites the Hassler 2014 background (8.75 µGy/h) for a value taken from the September 2017 event curve. The Plan chips "O2 out" and "Battery out" say SIM while their tooltip says "Registry entry: DERIVED". Write each label from the same registry entry as its tag. See D3 and D4.
9. **Start EVA cannot proceed when pointer lock is denied.** After #167 the start screen waits for pointer lock. When the browser denies it or `requestPointerLock` is missing (`src/engine/pointerLock.js:100`), the dialog shows "Mouse capture was not granted" and retries the same request, and the mode switch behind it is inert. That locks out iframes without `allow-pointer-lock`, touch devices and some screen-share setups. Offer "Continue without mouse capture" after one failure and fall back to drag-to-look. See F5.
10. **Plan map waypoint labels are unreadable and numbered differently from the cost table.** The Plan map labels are canvas sprites about 5 CSS px tall at 1920 x 1080. The map numbers HAB 1 and WP1 2, while the cost-per-leg table numbers WP1 1. Draw labels at a fixed screen size of at least 12 px and use one numbering. See U3.
11. **Crosshair and controls help for sampling.** A canvas click collects whatever sits under screen centre (`src/engine/sampling.js:190-197`), but no crosshair is drawn, and the rock only becomes a target at about 0.9 rad of pitch from 1.2 m. The controls help from #167 lists no sampling keys (P, click, E, F) and no layer, sources (C) or partner (T) keys. Draw a crosshair that lights up when a target is in reach and list the keys. See F6.
12. **Slope-ahead zone draws an unlit red lattice over the terrain.** `src/engine/slopeZone.js` draws 2.7 m quads on a 3 m grid with `MeshBasicMaterial` at 0.38 opacity. Sunlit and shaded slopes turn the same flat red and the 0.3 m gaps read as a dark grid. Draw the zone in the terrain shader, or close the gaps and multiply by the terrain shading. See T3.
13. **Show the active data layer and its legend in Walk.** A layer picked in Plan stays on in Walk and turns the view red and green with no legend or label, which reads as a rendering bug. Add a small layer chip with the legend colours to the HUD while a layer is active. See F7.
14. **Plan layer panel clips its legend at 1366 x 768.** The Map layers panel ends at y 654 while its content runs to y 805, hiding the legend source line and the tile facts. The route panel's Waypoints row is also below the fold. Let the legend scroll or collapse the overlay note under 800 px of height. See U2.
15. **Dust storm keeps full sun and sharp shadows on the ground at τ 5.** At τ 5.3 the sky closes in, but the foreground keeps clear-day brightness and crisp shadows, before and after #165. Scale the direct sun term and shadow contrast with optical depth in `src/engine/stormLight.js`. See T6.
16. **Measure tiers on the demo laptop.** The engine reports 534 k triangles and 62 draw calls at spawn on Low and 1.47 M and 64 on High, against 0.42 M and 1.25 M in the README "Tiers" table. Frame time could not be measured in the QA browser (SwiftShader). Run `npm run measure` on the demo machine with the habitat, partner and storm, and update the table. See Technical.
17. **Load terrain.json and the data JSON once, and drop terrain_tiles.glb from the deploy.** `terrain.json` (1.19 MB compressed) is fetched and parsed by four modules, and hazards.json and route.json are requested three times each on a cold load. `terrain_tiles.glb` and `.json` (1.74 MB) ship but nothing loads them. Share one loader promise per file and exclude the tiles from `public/`. See Technical.
